# 技术路径详解（最优方案）

**文档日期**：2026-04-26
**对应实验批次**：`complete_supervised_retrain_overnight_complete_20260331_001`（2026-03-31 至 2026-04-03）
**最优配置**：BGE-M3 + 对齐增强 + 智能混合（vector_with_llm）
**核心结果**：MRR=0.8271、Hits@1=0.7815、Hits@5=0.8874、Hits@10=0.9032（444 条标注查询）

---

## 1. 总体架构

本方案是一条「离线知识组织 → 实体链接 → 跨语言实体对齐 → 知识支撑接口」的四层链路。前一层为后一层提供已经规整好的对象与证据；最终的最优结果出现在第二层（实体链接），第三层（实体对齐）既独立可用，也作为第二层的"对齐增强"输入。

```
┌──────────────────────────────────────────────────────────────────┐
│ 第一层  离线知识组织                                                │
│   多源数据 → 字段清洗/补全 → 实体词抽取 → 向量编码 → JSONL → ES 索引 │
└────────────────────────────┬─────────────────────────────────────┘
                             │ 统一实体对象（label / aliases / desc / entity_words / vectors）
                             ▼
┌──────────────────────────────────────────────────────────────────┐
│ 第二层  实体链接（最优 0.8271）                                       │
│   文本 → NER 提及抽取 → BGE-M3 候选检索（含对齐增强） → 选择性 LLM 重排 │
└────────────────────────────┬─────────────────────────────────────┘
                             │ ⬅ 复用第三层产出的对齐预测进行内容注入
                             ▼
┌──────────────────────────────────────────────────────────────────┐
│ 第三层  跨语言实体对齐                                                │
│   原始语义向量 → 一跳星形邻域 → GAT 选择性聚合 → 拼接融合 → 对比学习训练 │
└────────────────────────────┬─────────────────────────────────────┘
                             │ 实体级 zh ↔ en 对齐预测（best: BGE-M3 + Graph）
                             ▼
┌──────────────────────────────────────────────────────────────────┐
│ 第四层  kg_rag 知识支撑接口                                           │
│   查询路由 → 实体/关系/三元组检索 → 对齐扩展 → 分层结构化证据         │
└──────────────────────────────────────────────────────────────────┘
```

## 2. 第一层：离线知识组织

### 2.1 数据源

| 数据源 | 用途 |
|---|---|
| Wikidata | 结构化实体标识、标签、别名 |
| Wikipedia | 自然语言描述、语义补充 |
| 领域监督标注数据 | NER 模型微调训练集 |
| DBP15K zh_en | 跨语言实体对齐基准（13347 候选 / 1206 测试 / 1250 验证） |

### 2.2 统一实体对象字段设计

| 字段 | 类型 | 用途 |
|---|---|---|
| `label` | 文本 | 实体标准名 |
| `aliases_zh` / `aliases_en` | 文本列表 | 别名扩展召回 |
| `descriptions_zh` / `descriptions_en` | 文本 | 语义检索补充 |
| `entity_words_zh` / `entity_words_en` | 文本列表 | 局部关键词检索（由描述抽取） |
| `_entity_words_*_vector` | 1024 维向量 | 向量近邻搜索 |
| `_entity_freq_*` / `_entity_count_*` | 词频字典 / 整数 | 信息完整度统计 |
| `link` | keyword | 去重键与溯源 |

### 2.3 处理流水线

```
原始数据 → 字段清洗与归一化 → 描述补全与别名补充 → 实体词抽取与统计
       → Transformer 向量编码（1024d，L2 归一化）
       → JSONL 落盘（zh_wiki_v2.jsonl / en_wiki_v3.jsonl）
       → entity_words_zh.jsonl / entity_words_en.jsonl
       → Elasticsearch 多字段索引
```

跨语言合并：当同一实体同时具备中英文向量时，通过均值池化 + L2 归一化得到合并向量 `label_vector`。

### 2.4 索引层结构

- **文本检索层**：`label`、`aliases_*`、`descriptions_*`、`content`（基于 BM25 的多字段 should 匹配）
- **关键词增强层**：`entity_words_zh`、`entity_words_en`
- **向量近邻层**：`entity_words_*_vector`、`label_vector`、`label_*_vector`、`descriptions_*_vector`

## 3. 第二层：实体链接（最优结果产出层）

### 3.1 提及抽取（NER 入口）

**HybridMentionExtractor**（混合提及抽取）：
1. **字典抽取**：基于实体标签与别名构造别名字典；长度优先的贪心匹配；专门处理 URL、超长别名、拉丁/CJK 字符边界
2. **Transformer NER**：基于 Hugging Face `token classification` 框架对 BERT 系预训练编码器进行监督微调；fast tokenizer 保留 offset mapping；动态构造 B-/I- 标签映射
3. **Hybrid 回退**：优先采用 Transformer 输出，模型未抽取到实体时回退至字典匹配

**训练配置**：
- 优化器：AdamW
- 学习率：5e-5；权重衰减：0.01
- 训练样本：2679；验证样本：444
- 训练轮数：5（最优 epoch 4）
- 最大长度：256；批大小：4

**结果**：Token Accuracy=0.9737，正类 F1=0.8037（Precision 0.8342 / Recall 0.7754）

### 3.2 BGE-M3 多语言候选检索 + KB 对齐内容注入（关键创新）

**编码器**：BGE-M3
- Mean Pooling
- 1024 维向量
- L2 归一化
- 对比学习预训练目标（dense + sparse + multi-vector 多视角联合约束，本方案仅使用 dense）

**KB 跨语言对齐内容注入**：
- 用第三层训练好的对齐模型（BGE-M3 + Graph）以**置信度阈值 t=0.75** 预测 zh→en 实体对
- 把英文实体的别名与描述合并进对应中文实体
- 取**中英向量的均值**作为融合向量，使中文实体在多语言语义空间中的几何位置更精确

**召回**：余弦相似度 Top-10，主检索字段为 `entity_words_*_vector`

### 3.3 选择性大模型重排序（智能混合）

**置信度自适应策略**：
- 计算 `confidence = top1_score − top2_score`
- 若 `confidence > 阈值`：直接返回 top-1（信任向量检索）
- 否则：调用大模型（GLM-4）对 Top-10 重排（在歧义边界处引入语义理解）

**为何选择性而非强制全量调用**：
- 强制每条都调用 LLM 会带来精度下降（混合语言的候选文档对中文 LLM 排序产生负面干扰）
- 仅在向量检索置信度不足时介入，可保留向量高效性 + LLM 深度判别

### 3.4 评测协议

- 评测集：`find.xlsx`（444 条标注查询）
- 指标：MRR、Hits@1、Hits@5、Hits@10
- 排序视角：每条查询计算正确实体在候选排序中的位置

### 3.5 最终结果

| 指标 | 数值 |
|---|---|
| MRR | **0.8271** |
| Hits@1 | **0.7815** |
| Hits@5 | **0.8874** |
| Hits@10 | **0.9032** |

## 4. 第三层：跨语言实体对齐

### 4.1 数据集

DBP15K zh_en：
- 候选实体数：13347（每侧）
- 测试对齐对：1206
- 验证对齐对：1250
- 划分：train / valid / test

### 4.2 原始语义基线

| 基线 | 类型 | 维度 | 角色 |
|---|---|---|---|
| LaBSE | 句向量型跨语言模型（双塔 BERT，[CLS] 表示，AMS + MLM + TLM） | 768 | 对照基线 |
| BGE-M3 | 检索型多语言强基线（dense/sparse/multi-vector 联合训练，自知识蒸馏） | 1024 | 重点基线 |

匹配公式：`score(e_s, e_t) = cos(h_{e_s}, h_{e_t})`

### 4.3 邻域结构构造

- **类型**：一跳星形邻域（中心实体 + 一跳邻居）
- **大小**：neighbor_size = 20
- **裁剪策略**：吸收一跳相连且已有向量表示的实体；超出固定大小裁剪
- **训练 / 评测**：使用相同邻域构造策略

### 4.4 模型结构

```
原始语义向量 ──┬─→ 中心实体表示 c
              │
              └─→ 星形邻域 H ─→ GAT 选择性聚合 → 邻域增强表示 h̃
                                                        │
                              [L2(c); L2(h̃)] ──→ MLP 融合 W_fuse → L2 归一化 → 对齐表示 o
```

**图注意力（GAT）核心公式**：
- 线性映射：`H' = HW`
- 注意力分数：`e_ij = LeakyReLU(a_s · h'_i + a_t · h'_j)`
- 归一化：`α_ij = softmax(e_ij)`
- 加权聚合：`h̃_i = Σ_j α_ij · h'_j`

**融合映射**：
- `ô = W_fuse · [L2(c); L2(h̃_0)] + b_fuse`
- `o = L2(ô)`
- W_fuse ∈ ℝ^(d × 2d)，Xavier 均匀初始化，bias 初始化为 0

**单层设计原因**：13347 实体规模下深层图传播容易引入过平滑（over-smoothing），损害细粒度判别。一跳已能覆盖局部主要判别信号，加深层数难以稳定提升性能。

### 4.5 训练机制：动量对比学习

**核心**：
- 动量教师网络（Momentum Contrast）
- 负样本队列（跨批次负样本）
- InfoNCE 损失

**损失函数**：
```
L = -log [exp(q·k/τ) / (exp(q·k/τ) + Σ_i exp(q·n_i/τ))]
```

**超参数**：
- queue_length = 64
- temperature τ = 0.08
- momentum = 0.9999
- batch_size = 64（训练）/ 128（评测）
- 学习率 = 1e-6
- dropout = 0.3
- 训练轮数 = 150
- 选择指标 = valid_hits@1

### 4.6 训练摘要

| 模型 | 最优轮次 | 验证 Hits@1 | 测试 MRR | 训练时长 |
|---|---|---|---|---|
| LaBSE + Neighbor Graph | 147 / 150 | 0.623 | 0.696 | 34705s |
| BGE-M3 + Neighbor Graph | 40 / 150 | 0.662 | 0.725 | 43567s |

## 5. 第四层：kg_rag 知识支撑接口

### 5.1 服务定位

kg_rag 不重新训练模型，而是消费前三层产出的实体识别、候选召回与对齐能力，将其封装为可调用的结构化证据接口。属于"证据准备层"和"知识支撑层"，**不包含完整生成闭环验证**。

### 5.2 查询路由（意图识别）

| 输入模式 | 意图 |
|---|---|
| `kg1:123` 或 `1:123` | 实体详情查询 |
| `rel1:106` 等 | 关系详情查询 |
| 包含"关系"、"三元组"等关键词 | 关系检索 |
| 其余自然语言 | Hybrid 模式（ES text_search + 本地实体名 / 关系名搜索） |

ES 不可用时自动回退到本地搜索路径。

### 5.3 输出槽位

`query()` 接口统一返回六类证据：
- `entities`
- `relationships`
- `triples`
- `alignments`
- `chunks`
- `references`

`metadata` 字段记录查询模式、意图识别结果与处理过程。

### 5.4 证据分级

| 来源 | 可信级别 | 标记 |
|---|---|---|
| 直接命中实体详情、本地三元组 | 高 | — |
| Gold 对齐（DBP15K split=test/valid/train） | 高 | `split=test/valid/train` |
| 模型预测对齐扩展 | 中 | `split=predicted`、`evidence=raw_embedding:...` |
| ES 外部参考 | 中 | — |

### 5.5 扩展能力

- 受控的一跳 BFS 子图提取
- 以实体为中心组织局部知识上下文供上层推理使用

## 6. 关键设计决策与依据

| 决策 | 依据 |
|---|---|
| BGE-M3 优先于 LaBSE 作为重点基线 | 检索型对比学习训练目标，dense+sparse+multi-vector 多视角约束保留更多局部判别信号 |
| 对齐增强采用 t=0.75 阈值 | 在召回与噪声之间平衡，过低会引入错误的英文内容污染中文实体语义空间 |
| 选择性 LLM 重排 vs. 全量调用 | 全量调用会让混合语言文档对中文 LLM 排序产生负面干扰；选择性介入既保留向量效率又利用 LLM 深度理解 |
| 单层 GAT、一跳邻域 | 13347 实体规模下深层传播过平滑严重；一跳已覆盖主要判别信号 |
| 动量对比学习 | 通过队列实现跨批次大规模负样本，稳定排序约束的学习 |
| valid_hits@1 作为模型选择指标 | 对齐任务的应用价值首先在于"等价实体能否被排到首位" |
| kg_rag 不做生成闭环 | 实体链接与对齐是当前最可靠的可复现证据；生成端自动化评测尚未形成同等强度的验证基础 |

## 8. 一句话总结

> 先用统一实体对象稳定知识底座；以 BGE-M3 多语言向量检索为主召回，借助跨语言对齐模型把英文实体内容注入中文实体以精确多语言空间几何位置，再通过置信度自适应的选择性 LLM 重排完成歧义边界消歧；同时以"BGE-M3 + 一跳 GAT 邻域增强 + 动量对比学习"独立训练对齐模型，既为实体链接提供对齐预测，也作为完整的跨语言对齐能力被 kg_rag 封装为可调用的分层证据。
