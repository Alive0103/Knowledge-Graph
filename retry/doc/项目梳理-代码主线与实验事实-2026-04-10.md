# 项目梳理：代码主线与实验事实

整理时间：`2026-04-10`

## 1. 边界约定

- `Knowledge-Graph/retry` 是当前毕业设计中最完整、最适合作为正式论文依据的一套代码。
- 其他目录中的实现可以参考，但不建议直接写成“本文正式实现结果”。
- 正式实验结果优先引用 `retry/output/` 下的 JSON 和 Markdown 汇总文件。

## 2. 当前项目的实际主线

从代码和已有产物看，`retry` 当前最完整的链路不是泛化的“全功能知识图谱系统”，而是下面这条更扎实的实验主线：

1. 多源数据整理与离线知识组织
2. 领域实体识别与实体链接候选检索评测
3. DBP15K `zh_en` 跨语言实体对齐
4. 对齐结果汇总与教师汇报报告生成
5. 面向知识服务的接口封装与原型衔接

因此，正式论文建议把“实体链接 + 实体对齐”作为两条核心实验主线，把“知识库构建 + RAG 接口”作为系统支撑与应用落点。

## 3. 主要代码模块

| 路径 | 作用 | 论文中的对应位置 |

| `retry/run_complete_supervised_retrain_suite.py` | 完整重训与汇总入口 | 第5章 |

## 4. 关键脚本职责速记

### 4.1 `run_rigorous_full_experiment.py`

- 严格顺序执行完整实验链。
- 会把实体链接训练、ES 评测、对齐训练、对比报告串起来。
- 会持续刷新 `state.json`，适合作为“正式流程入口”在论文中描述。

### 4.2 `run_complete_supervised_retrain_suite.py`

- 用于生成完整重训汇总结果。
- 会整合实体链接评测和实体对齐评测。
- 适合作为“汇总结果来源”引用。

### 4.3 `run_entity_linking_es.py`

- `index` 子命令负责导入 ES。
- `eval` 子命令正式支持的评测模式是 `text`、`vector`、`both`。
- 当前论文里最稳妥的实体链接结果，就是由这里沉淀出来的 `text_only` 和 `vector_only`。

### 4.4 `alignment/model.py`

- 图模型核心是图注意力聚合。
- 先得到中心实体的语义表示，再聚合邻居表示。
- 最终把中心语义与邻域结构信息融合，输出对齐表示。

## 5. 当前最可靠的实验事实

这些结论是从 `retry/output/` 下的结果文件直接整理出来的，适合作为正式论文优先引用版本。

### 5.1 实体链接

来源：

- `retry/output/entity_linking_training/ner_finetuned_distilbert_mbert_rigorous_full_overnight_complete_20260331_001_labse/training_summary.json`
- `retry/output/complete_supervised_retrain_overnight_complete_20260331_001/combined_summary.json`

结论：

- 领域 NER 最优验证集正类 F1 为 `0.8037`
- `text_only` 检索结果：
  - `MRR=0.6536`
  - `Hits@1=0.5676`
  - `Hits@5=0.7635`
  - `Hits@10=0.8063`
- `vector_only` 检索结果：
  - `MRR=0.0293`
  - `Hits@1=0.0158`
  - `Hits@5=0.0450`
  - `Hits@10=0.0698`

可得出的稳定结论：

1. 在当前项目设置下，文本检索显著优于纯向量检索。
2. 领域实体识别模型已能为实体链接提供较稳定入口。
3. 当前实体链接主线应写成“NER + ES 文本候选检索”，而不是“向量检索主导”。

### 5.2 实体对齐

来源：

- `retry/output/complete_supervised_retrain_overnight_complete_20260331_001/combined_summary.json`
- `retry/output/alignment_training/labse_neighbor_retrained_zh_en_rigorous_full_overnight_complete_20260331_001_labse/summary.json`
- `retry/output/alignment_training/bge_m3_neighbor_retrained_zh_en_overnight_complete_20260331_001_bge_graph/summary.json`

结论：

| 方法 | MRR | Hits@1 | Hits@5 | Hits@10 |
| --- | ---: | ---: | ---: | ---: |
| Raw LaBSE baseline | 0.478 | 0.410 | 0.559 | 0.606 |
| LaBSE + neighbor graph model | 0.696 | 0.631 | 0.773 | 0.810 |
| Raw BGE-M3 baseline | 0.679 | 0.624 | 0.745 | 0.776 |
| BGE-M3 + neighbor graph model | 0.725 | 0.670 | 0.794 | 0.833 |

可得出的稳定结论：

1. 邻域图增强对 `LaBSE` 和 `BGE-M3` 两条主线都有效。
2. `LaBSE` 主线的“对齐前 vs 对齐后”对比最清晰，适合在论文里做主线叙述。
3. 当前综合最优结果来自 `BGE-M3 + neighbor graph model`。

## 6. 论文写作映射建议

### 6.1 最推荐的正文重心

- 第1章：绪论
- 第2章：相关技术与总体方案
- 第3章：离线知识组织与实体链接
- 第4章：跨语言实体对齐
- 第5章：实验设计与结果分析

### 6.2 “知识百科构建”怎么写

不建议把“知识百科构建”写成一个空泛的大系统口号，建议落到这几个具体点：

- 多源数据采集与清洗
- 实体标签、别名、描述、关键词与向量字段设计
- ES 单索引多字段存储与离线检索支撑

### 6.3 “检索增强生成”怎么写

建议把题目中的 RAG 写成“应用目标”和“系统支撑层”，而不是全文唯一核心实验对象。更稳妥的写法是：

- 先证明实体链接能提升知识命中与实体规范化能力
- 再证明实体对齐能扩展跨语言知识边界
- 最后说明这些能力如何为 RAG 提供可靠证据

## 7. 写作中的高风险点

### 7.1 不要直接沿用旧结果

中期报告中的一些数字和当前 `retry/output` 最新汇总存在差异。正式论文里如果写“最终结果”，必须优先用 `retry/output` 当前版本。

### 7.2 不要过度承诺未正式落地内容

以下内容如果没有额外可追溯实验，不建议写成“正式结论”：

- 完整 LLM 重排序效果
- 动态混合检索最终收益
- 大规模系统级 RAG 自动评测

更稳妥的表述方式：

- 方案设计
- 阶段性探索
- 后续优化方向

### 7.3 第6章可灵活处理

如果答辩前 `kg_rag` 相关集成不足，可以把系统部分缩成一节，把篇幅集中在第3章到第5章，这样更稳。

## 8. 一句话版论文定位

可以把整篇论文浓缩成一句话：

> 本文以离线知识组织为基础，以实体链接和跨语言实体对齐为核心实验主线，面向军事领域知识服务场景，为后续检索增强生成提供可信、可追溯的知识支撑。
