# 项目技术分析文档

> 本文档整理了项目"融合内外部数据的知识百科构建与检索增强生成"的核心技术细节，供毕业论文写作参考。

## 一、项目总体架构

### 1.1 研究目标

构建一个融合内部私有知识与外部开放知识的知识百科系统，实现：
- 离线知识库构建（多源数据采集、清洗、结构化存储）
- 实体链接（命名实体识别 + 候选召回 + 排序消歧）
- 跨语言实体对齐（中英文知识图谱实体匹配）
- 检索增强生成（RAG，知识检索 + LLM生成）

### 1.2 技术路线总览

```
数据采集(Wikidata/维基百科/DBP15K)
    ↓
数据预处理(清洗/补全/结构化)
    ↓
Elasticsearch索引构建(文本+向量混合索引)
    ↓
实体链接(NER→候选召回→排序→消歧)
    ↓
跨语言实体对齐(LaBSE+GAT邻域聚合+对比学习)
    ↓
RAG检索增强生成(意图检测→混合检索→知识融合→生成)
```

## 二、实体链接模块 (entity_linking/)

### 2.1 NER模型微调

**基座模型**: Chinese-RoBERTa-wwm-ext-large (隐藏维度1024)

**标注体系**: BIO/BIOES格式，支持多类型实体(B-ENTITY, I-ENTITY等)

**训练策略**: 渐进式解冻
- 第一阶段：冻结前12层，仅微调后12层
- 第二阶段：逐步解冻更多层直至全参数微调

**训练超参数**:
| 参数 | 值 |
|------|-----|
| max_length | 192 tokens |
| batch_size | 4 |
| learning_rate | 5e-5 |
| weight_decay | 0.01 |
| 损失函数 | CrossEntropyLoss (忽略padding) |

**四源融合数据策略**: 统一BIO标注格式，打乱来源避免过拟合

**评估结果**: 准确率98.22%，精确率97.98%，召回率98.54%，Micro-F1 98.26%

### 2.2 实体抽取后端

#### 字典匹配抽取 (DictionaryMentionExtractor)
- 别名归一化，过滤URL和超长别名(>80字符)
- 按长度降序排列，贪心匹配避免重叠
- CJK检测(U+3400-U+9FFF)，拉丁词边界正则

#### Transformer NER抽取 (TransformerMentionExtractor)
- 基于HuggingFace AutoModelForTokenClassification
- 支持fast tokenizer的offset mapping用于字符级重构
- 最大序列长度512 tokens

#### 混合抽取 (HybridMentionExtractor)
- 优先使用Transformer结果，空结果时回退至字典匹配

### 2.3 实体向量化

#### 哈希向量化 (HashingVectorizer)
- Blake2b哈希，8字节摘要
- 特征：全文、压缩文本、2-gram/3-gram字符n-gram
- L2归一化，默认1024维

#### Transformer向量化 (TransformerVectorizer)
- 使用sentence-transformers编码
- CLS token作为句向量，batch_size=32
- 维度不匹配时零填充或截断，最终L2归一化

### 2.4 Elasticsearch索引设计

**索引字段**:

| 字段类型 | 字段名 | 权重/说明 |
|---------|--------|----------|
| 文本(精确) | label/label_zh/label_en | boost=4.0 |
| 文本(别名) | aliases_zh/aliases_en | boost=3.0 |
| 文本(描述) | descriptions_zh/descriptions_en | boost=1.5 |
| 文本(关键词) | entity_words_zh/entity_words_en | - |
| 向量(1024维) | entity_words_zh_vector | cosine |
| 向量(1024维) | entity_words_en_vector | cosine |
| 向量(合并) | label_vector | zh+en均值→L2归一化 |

**检索方式**:
1. **纯文本检索**: BM25 + 多字段加权 → MRR=0.654, Hits@1=0.568
2. **纯向量检索**: KNN向量搜索 → MRR=0.022 (效果较弱)
3. **混合检索**: 文本+向量结合

**分析器**: ik_max_word (中文分词)

### 2.5 实体链接检索路径

最终制定的检索策略：
1. ES文本检索作为主召回通道（稳定性强）
2. 向量检索作为补充
3. 低置信度/困难样本启用LLM判别（动态混合策略）
4. LLM辅助提及规范化和候选重排序

## 三、跨语言实体对齐模块 (alignment/)

### 3.1 数据集: DBP15K

- **语言对**: 中文-英文 (zh_en)
- **测试集规模**: 1206对实体对齐样本
- **数据格式**: 实体ID映射、关系ID映射、三元组、对齐对(train/valid/test)

### 3.2 模型架构: LaBSE + 单层单头GAT

#### 输入表示
- 每个实体: 自身embedding + K个最近邻embedding + 邻接矩阵
- 输入维度: (batch, neighbor_size+1, embedding_dim + neighbor_size+1)
- neighbor_size = 20

#### BatchMultiHeadGraphAttention

数学公式:
```
h' = h · W                          (线性变换)
attn_src = tanh(h') · a_src         (源注意力)
attn_dst = tanh(h') · a_dst         (目标注意力)
attn = softmax((attn_src + attn_dst^T) / √d)  (缩放点积注意力)
output = attn · h'                   (注意力聚合)
```

#### 前向传播流程
1. 分离embedding和邻接矩阵
2. 提取中心实体表示 (第0位)
3. GAT邻域聚合 (1层)
4. 可选归一化 (center_norm, neighbor_norm, emb_norm)
5. 中心+邻域拼接后MLP融合 (embedding_dim*2 → embedding_dim)

### 3.3 训练策略: 动量对比学习 (MoCo风格)

**核心思想**: 维护教师网络产生稳定的负样本

**训练过程**:
```
for each batch:
    1. 学生模型前向: student_out = student(positive_batch)
    2. 教师模型前向(无梯度): teacher_out = teacher(positive_batch)
    3. 教师产生负样本: neg_vectors = teacher(queue_batches)
    4. 对比损失: L = -log(exp(sim(s,t)/τ) / Σexp(sim(s,n_i)/τ))
    5. 动量更新教师: θ_t = m·θ_t + (1-m)·θ_s
```

**关键超参数**:

| 参数 | 值 | 说明 |
|------|-----|------|
| epochs | 150 | 训练轮数 |
| batch_size | 64 | 训练批次 |
| queue_length | 64 | 负样本队列长度 |
| learning_rate | 1e-6 | 学习率 |
| temperature (τ) | 0.08 | 温度系数 |
| momentum (m) | 0.9999 | 动量系数 |
| neighbor_size | 20 | 邻域大小 |
| dropout | 0.3 | Dropout率 |
| gradient_clip_norm | 1.0 | 梯度裁剪 |

### 3.4 评估方法

**指标**: MRR, Hits@1, Hits@5, Hits@10

**评估流程**:
1. 对每个测试实体，通过模型获取embedding
2. 计算与目标知识图谱所有实体的余弦相似度
3. 排序得到目标实体的排名
4. 批量评估(batch=256)，向量化numpy操作

### 3.5 实验结果

| 方法 | MRR | Hits@1 | Hits@5 | Hits@10 |
|------|-----|--------|--------|---------|
| Raw LaBSE基线 | 0.478 | 0.410 | 0.559 | 0.606 |
| LaBSE + 邻域图 | **0.690** | **0.621** | **0.773** | **0.810** |
| Raw BGE-M3基线 | 0.679 | 0.624 | 0.745 | 0.776 |

**关键发现**:
- 邻域图注意力使LaBSE的MRR提升44.4% (+0.212)
- 图结构信息有效增强了跨语言实体表示的判别能力

## 四、KG-RAG模块 (kg_rag/)

### 4.1 查询意图检测

优先级排序：
1. **正则匹配**: kg1:6426 → 实体查找；rel1:106 → 关系查找
2. **文本模式**: "三元组"/"triple" → 三元组查找；"关系" → 关系搜索
3. **默认**: hybrid混合检索

### 4.2 混合检索流程

```
用户查询
  ↓
意图检测 → 确定查询类型
  ↓
ES实体链接(text_search) → 外部参考 + 文本片段
  ↓
分支处理:
  ├─ entity_lookup: 实体详情 + 关系 + 三元组 + 对齐
  ├─ relation_lookup: 关系详情 + 样例三元组
  └─ hybrid: 本地实体搜索 + 关系搜索 → 合并结果
  ↓
对齐扩展(可选): 查找跨语言等价实体
  ↓
输出组装: entities + relationships + triples + alignments + chunks
```

### 4.3 对齐扩展机制

1. **金标准对齐查找**: 在train/valid/test/ref集中查找已知对齐
2. **预测对齐**: 若无金标准，使用训练好的embedding计算相似度，返回Top-K候选

### 4.4 子图构建

- BFS图扩展，最大深度1，最大节点50
- 种子选择：按关系频率选择Top-K实体
- 输出：nodes + edges 的图结构

## 五、完整实验流水线

### 执行顺序 (run_rigorous_full_experiment.py)

1. **资源准备** → 验证路径、ES配置、DBP15K数据
2. **NER模型训练** → 下载基座模型 → 准备数据 → 微调
3. **实体链接流水线** → 抽取 → 向量化 → 输出JSONL
4. **ES索引与评估** → 建索引 → 文本检索评估 → 向量检索评估
5. **LaBSE基线评估** → 构建/加载embedding → 测试集评估
6. **对齐模型训练** → GAT模型训练 → 保存最佳模型
7. **BGE-M3基线(可选)** → 构建embedding → 评估
8. **报告生成** → 对比报告(对齐前后效果)

**状态管理**: 每步写入state.json用于监控进度
