## 1. 使用说明

- 正式代码与正式实验结果以 `Knowledge-Graph/retry` 为准，其他目录中的代码只作为参考，不直接写成“本文已实现/已验证”。
- 正式实验指标优先引用 `retry/output/` 下最新、可追溯的 JSON 和 Markdown 汇总文件。
- 当前最稳妥的论文主线是：`离线知识组织 -> 实体链接 -> 跨语言实体对齐 -> 面向 RAG 的知识支撑接口/原型`。
- 如果答辩前 `kg_rag` 联调结果充足，可保留独立的“系统集成与应用展示”章节；如果联调仍偏原型，可将其写成总体方案中的一节，避免正文重心失衡。
- 开题报告和中期报告中的背景、意义、研究内容、技术路线可以继续沿用，但具体实验数字要以 `retry` 当前版本的可复现结果为准。

## 2. 格式速记

- 全文不少于 `15000` 字。
- 章标题用黑体三号居中，节标题用宋体四号居中，正文中文用宋体小四，英文用 `Times New Roman` 小四。
- 中文摘要一般约 `300` 字，关键词 `3-5` 个；英文摘要与中文摘要内容一致。
- 目录放在中英文摘要之后。
- 主体部分通常包括：绪论（引言）、正文、结论、结束语、致谢、参考文献、附录。
- 图题放图下方，表题放表上方，按章编号，例如 `图3.2`、`表4.1`。
- 正文双面打印，页边距和页眉页脚按照学校规范执行。

## 5. 正文模板

### 第1章 绪论

#### 1.1 研究背景与意义

这一节建议围绕以下三层展开：

- 第一层：大语言模型与 RAG 推动知识服务升级，但通用模型在专业领域存在知识边界与可信性问题。
- 第二层：内部私有知识与外部开放知识长期割裂，实体命名不统一、描述不完整、跨语言映射困难。
- 第三层：军事等特殊领域对无网运行、知识可追溯和结果可信性要求更高，因此需要离线知识组织、实体链接、跨语言对齐与知识增强生成协同设计。

可直接起笔的句式：

> 随着大语言模型和检索增强生成技术的快速发展，面向组织级知识服务的智能系统正在从“文本检索”向“知识理解与生成”演进。然而，在军事等特殊领域中，知识来源分散、实体表达复杂、跨语言知识难以统一组织等问题依然突出，导致通用知识服务框架难以直接满足高可信、可追溯、可离线部署的应用需求。

建议插图或表格：

- 图1.1 研究背景与问题定义示意图

#### 1.2 国内外研究现状

建议拆成三个子方向写：

##### 1.2.1 实体链接研究现状

写作提示：

- 国内研究重点写中文场景、专业领域定制、知识库增强、多任务学习等方向。
- 国外研究重点写双编码器检索、交叉编码器排序、端到端实体链接、零样本与低资源场景。
- 最后落到“专业领域、复杂别名、离线场景、可解释检索”这些尚未完全解决的问题。

##### 1.2.2 实体对齐研究现状

写作提示：

- 国内可写跨语言、跨领域、结构语义联合建模、多模态扩展。
- 国外可写跨域适配、领域自适应、结构增强、图神经网络与对比学习。
- 最后指出：仅靠名称或仅靠结构都存在局限，语义与邻域关系联合建模仍然是有效路线。

##### 1.2.3 RAG 与知识增强生成研究现状

写作提示：

- 国内重点写中文场景适配、轻量化、小模型、GraphRAG 等。
- 国外重点写知识图谱增强 RAG、多模态 RAG、动态更新、闭环优化。
- 结尾要指出：在高可信、可离线、实体级可追溯场景下，RAG 仍依赖更稳定的知识组织与实体理解能力。

##### 1.2.4 现有研究不足总结

建议凝练为 `3-4` 点：

1. 针对军事领域等特殊场景的实体表达复杂，通用实体链接方法适配性不足。
2. 内外部知识之间缺少稳定的跨语言实体映射机制，影响知识扩展与融合。
3. 许多 RAG 研究更关注生成端，较少系统处理实体链接与知识对齐对生成质量的影响。
4. 无网或弱网场景下的离线可部署性、知识可信性与证据追溯仍需加强。
