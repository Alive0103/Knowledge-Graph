# 开题与中期材料提炼

整理时间：`2026-04-10`

本文档用于把开题报告和中期报告中可继续使用的内容、需要校准的内容、适合写入毕业论文的叙事线索集中整理出来。

## 1. 开题报告中可直接继承的内容

### 1.1 题目

- 融合内外部数据的知识百科构建与检索增强生成

这个题目可以继续使用，但论文正文必须让“知识百科构建”“实体链接”“实体对齐”“检索增强生成”四者之间形成清晰层次。

### 1.2 研究背景与意义

开题报告里最值得保留的核心逻辑有三条：

1. 内部私有知识与外部开放知识长期割裂，缺乏统一知识表达与互操作机制。
2. 军事等特殊领域需要无网或弱网环境部署，对离线知识组织和可信检索有更高要求。
3. 自然语言中的多义性、模糊性和复杂命名方式导致实体识别与实体消歧困难，影响后续知识检索与生成质量。

这些内容非常适合直接写进论文第1章的“研究背景与意义”。

### 1.3 开题报告中的四项研究内容

开题报告提出的四项任务非常适合作为论文总体框架：

1. 本地知识库构建
2. 实体链接优化
3. 跨语言实体对齐
4. 军事领域 RAG 框架适配

正式论文建议把前两项和第三项写成核心实验主线，把第四项写成系统目标与应用落点。

### 1.4 开题中的问题定义

可直接转化为论文“研究难点”：

- 领域适配问题
- 语义理解与检索准确性问题
- 跨语言实体对齐问题
- RAG 融合与适配问题

## 2. 中期报告中可继续使用的素材

### 2.1 总体技术路线

中期报告已经形成了较完整的总体路线表述，可以继续沿用为：

- 多源数据采集与离线知识组织
- 领域实体识别与实体链接
- 跨语言实体对齐
- 面向 Graph/RAG 的知识扩展与证据支撑

这适合作为第2章的总体技术路线图文字说明。

### 2.2 知识库构建部分

中期报告提供了较多可复用素材：

- 以 `Wikidata` 作为结构化知识主来源
- 以 `Wikipedia` 补充实体语义描述
- 以 `DBP15K` 作为跨语言实体对齐标准数据集
- 采用 ES 支撑离线检索
- 字段设计包括：标签、别名、描述、关键词、向量

这些内容很适合沉淀到第3章“离线知识组织与实体链接方法设计”前半部分。

### 2.3 实体链接部分

中期报告里已经形成以下可复用写法：

- 实体链接任务需要先解决提及识别，再解决候选召回与排序
- 候选召回可从标准名、别名、描述等多个字段展开
- 评价指标采用 `MRR`、`Hits@1`、`Hits@5`、`Hits@10`

这些内容仍然适合进入最终论文，但具体实验数字需要按 `retry` 最新结果重写。

### 2.4 实体对齐部分

中期报告里已经有比较成熟的表述框架：

- 仅依赖名称或短描述不足以稳定区分等价实体
- 仅依赖图结构又可能在结构稀疏时失效
- 因此采用“跨语言语义表示 + 邻域图结构增强”的联合建模思路

这部分与 `retry/alignment/` 的当前实现非常吻合，适合保留为第4章主线。

## 3. 需要和当前 `retry` 结果对齐的内容

这是最终写论文时最需要注意的部分。

### 3.1 中期报告中的部分实验结果不是最终版本

中期报告里的某些数值更接近阶段性结果，正式论文如果写“最终实验结果”，优先使用 `retry/output/` 当前已落地的汇总文件。

例如：

- 中期报告中某些实体对齐指标与现在 `combined_summary.json` 不完全一致
- 中期报告中对实体链接多种方案的讨论更丰富，但 `retry` 当前正式沉淀结果主要是 `text_only` 与 `vector_only`

### 3.2 中期报告强调的 LLM 重排序需要谨慎下笔

中期报告中对 `纯LLM`、`向量+LLM重排序`、`动态混合` 的讨论较多，但 `retry` 当前正式、清晰、最适合写入论文主结果的实体链接评测仍是：

- `text_only`
- `vector_only`

因此建议：

- 如果没有额外稳定产物，LLM 部分写成“方案探索”或“后续优化方向”
- 不要把它写成论文最核心的正式实验结论

### 3.3 中期报告中的训练数据规模与当前汇总口径不同

中期报告中曾提到更大的多源 NER 数据配置；但当前 `retry/output/entity_linking_training/.../training_summary.json` 给出的正式可追溯结果口径是：

- 训练样本数：`2679`
- 验证样本数：`444`
- 标签数：`13`
- 最优 F1：`0.8037`

因此最终正文如果只基于 `retry` 当前版本写作，就优先用这套口径。

### 3.4 中期报告中的 RAG 内容更像“总体目标”而非“最终实验主线”

当前 `retry` 的最强项在于：

- 实体链接
- 实体对齐
- 实验汇总

`kg_rag` 更适合在论文中写成：

- 系统接口设计
- 应用原型
- 后续集成目标

而不是强行写成已经完成了大规模系统级评测的主线章节。

## 4. 最终论文建议叙事

### 4.1 最稳妥的总叙事

推荐最终叙事如下：

> 为解决特殊领域离线知识服务中的知识割裂、实体歧义和跨语言知识缺失问题，本文从多源数据组织出发，构建离线知识基础；随后以实体链接和跨语言实体对齐为核心实验主线，验证知识理解与知识补全能力；最后给出面向 RAG 的知识支撑接口与应用思路。

### 4.2 章节重心建议

- 第1章写清楚问题、意义、研究现状和论文结构
- 第2章写技术基础和总体方案
- 第3章写离线知识组织与实体链接
- 第4章写跨语言实体对齐
- 第5章写实验设计与结果分析
- 第6章按材料充分程度决定是否独立成章

### 4.3 贡献点建议

最终贡献点建议控制在 `3` 条左右，避免过散：

1. 面向离线场景的多源知识组织与实体字段设计
2. 面向领域文本的实体链接方法与正式评测分析
3. 融合语义表示与邻域图结构的跨语言实体对齐方法及实验验证

如果第6章系统集成较完整，再增加一条：

4. 面向知识增强生成的知识支撑接口设计与应用原型

## 5. 可直接复用的句式素材

### 5.1 背景句式

> 在军事等特殊领域中，知识来源分散、命名方式复杂、跨语言映射困难等问题并存，传统基于单一数据源或单一检索方式的知识服务框架难以同时满足离线部署、事实可信与结果可追溯等应用需求。

### 5.2 总体方案句式

> 本文以离线知识组织为基础，以实体链接和跨语言实体对齐为核心实验主线，在此基础上设计面向知识增强生成的知识支撑接口，形成从知识整理、知识匹配到知识利用的闭环流程。

### 5.3 实验结论句式

> 实验结果表明，在当前实体链接任务中，基于文本字段的候选检索方案明显优于纯向量检索；在跨语言实体对齐任务中，引入邻域图结构增强后，模型在不同语义表示基础上均取得了稳定性能提升，说明结构信息能够有效补充纯语义表示的不足。

## 6. 写论文时的具体提醒

### 6.1 先写什么

最推荐的写作顺序：

1. 第5章实验设计与结果分析
2. 第3章和第4章方法设计
3. 第2章总体方案
4. 第1章绪论
5. 摘要、结论、结束语

因为第5章最依赖现成事实，先写更容易稳定全文口径。

### 6.2 哪些地方最容易写虚

- 把参考代码写成了自己的正式实现
- 把中期阶段探索写成了最终结果
- 把 RAG 应用目标写成了已经完成的完整系统评测

### 6.3 最安全的证据来源

最终写作时，建议优先盯住下面这些文件：

- `retry/output/complete_supervised_retrain_overnight_complete_20260331_001/combined_summary.json`
- `retry/output/entity_linking_training/.../training_summary.json`
- `retry/output/alignment_training/.../summary.json`
- `retry/output/experiment_comparison/...`

## 7. 最终建议

一句话总结：

> 开题和中期材料中的“问题意识”和“总体方向”都可以继续用，但论文定稿时要把证据重心收束到 `retry` 当前已经跑通并可追溯的实体链接与实体对齐实验结果上。
